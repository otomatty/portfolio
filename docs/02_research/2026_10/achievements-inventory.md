## 0. 書き方のルール

### 1 件の実績は 4 段で書く

| 段 | 書くこと | 例（学習塾） |
|---|---|---|
| 目指したこと | 誰の、どんな負担やロスを、どこまで減らしたかったか | 講師の勤怠集計と給与計算に毎月取られる時間をなくす |
| 打ち手 | そのために何をしたか（技術は最後に一言） | 勤務記録を Web 化し、集計と給与計算を自動化 |
| 数値 | Before → After と、その差 | 月 20 時間 → 1 時間未満（95% 以上削減） |
| 根拠 | 数値の出どころ | 導入前後の作業時間をクライアントに確認 |

### 数値は 3 種類に分けて表示する

数値の種類を混ぜると信頼性が落ちるため、サイトでもラベルで区別します。

| 種類 | 意味 | 表示例 |
|---|---|---|
| 実測 | 導入前後を実際に測った値 | `実測` 注文時間 5 分 → 1 分 |
| 試算 | 単価や人数から計算した見込み額 | `試算` SaaS 費 年 ○○ 万円削減（○名 × 月 ○円 × 12） |
| 目標 | 設計時に置いた目標値（未達・測定前を含む） | `目標` 研修期間を 3ヶ月 → 2ヶ月 |

### 換算の式（金額にそろえる場合）

- 工数削減額 ＝ 削減時間（h/月）× 人数 × 時間単価 × 12
- SaaS 置き換え額 ＝ 利用人数 × 月額単価 × 12 −（自前運用のインフラ費 ＋ 保守工数）
- 期間短縮 ＝ 当初計画の期間 − 実際の期間（「計画比 ○%」で表す）

## 8. サイトに数値を載せるためのデータ構造案

`Work`（作品）と `SkillSheetProject`（案件）の両方に、共通の「成果」項目を足します。どちらも任意項目なので、既存データはそのまま動きます。

```ts
/** 数値の種類。サイト上でラベル表示する */
export type ImpactKind = 'measured' | 'estimated' | 'target';

/** 1 つの数値成果 */
export type Impact = {
  /** 何の数値か（例: 勤怠集計の作業時間） */
  label: string;
  before?: string; // 例: '月20時間'
  after?: string; // 例: '月1時間未満'
  /** 見出しにする値（例: '95%削減'、'年120万円'） */
  value: string;
  kind: ImpactKind;
  /** 算出根拠（例: '利用60名 × 月額500円 × 12'） */
  basis?: string;
};

/** 実績のストーリー */
export type Outcome = {
  /** 目指したこと（1〜2 文） */
  goal: string;
  /** 打ち手（箇条書き） */
  approach: string[];
  /** 数値成果（先頭がカードやハイライトに出る） */
  impacts: Impact[];
};

// Work と SkillSheetProject に `outcome?: Outcome` を追加する
```

表示の方針:

- 実績カード: タイトルの下に `goal` を 1 行、その下に `impacts[0]` を大きく（例: 「95% 削減｜勤怠集計の作業時間」）
- 詳細ページ: 目指したこと → 打ち手 → 数値（Before/After の対比）→ 根拠の順
- キャリアハイライト: 全実績の `measured` から代表値を選んで並べる（例: ベロシティ 2 倍／業務量 1/3／作業時間 95% 削減）
- `estimated` と `target` には「試算」「目標」のラベルを必ず付ける
