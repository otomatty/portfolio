# HTML Canvas / WebGPU によるデザイン刷新 モックアップと計画

> 本書は実装前の提案です。モックアップ（`mockup.html`）で方向性を確認したうえで、実装を別 PR に分けて進めます。
> v3: Hero の幾何学と実績の見せ方を、それぞれ3案に広げて比較できるようにしました。ページ全体にパララックスを入れています。

## モックアップの見方
`mockup.html` は `public/images/` の画像を相対パスで参照します。リポジトリ直下で HTTP サーバーを起動して開いてください。

```sh
bunx serve .   # /docs/03_plans/webgpu-redesign/mockup.html を開く
```

画面下のツールバーで、Hero の候補（A / B / C）、実績の候補（A / B / C）、描画方式（WebGPU / Canvas 2D）、注釈の表示を切り替えられます。

## 確定済みの方針（v2 まで）
- 配色は現行ダークの深緑 `hsl(136 31% 8%)` と金 `#D0A900` / `#987D00` に絞る。ライトテーマはなくす
- 書体は Inter と Noto Sans JP。見出しはウェイト 300 で字間を広くとる
- 写真はグレースケールにするだけにする（網点にはしない）

## Hero の候補
| 案 | 図形 | パララックス | 向いている点 | 気になる点 |
| --- | --- | --- | --- | --- |
| A 算額 | シュタイナーの円鎖。大小2つの円の間を9つの円が接しながら回り続ける。中心がのる楕円と接点も描く | 奥に分度器の目盛り、中央に円鎖、手前に大きな円鎖の影 | 線だけで余白が多い。和算の由来と数学の両方を語れる | 説明がないと図形の意味が伝わりにくい |
| B 麻の葉 | 大きさの違う麻の葉文様を3枚重ね、少しずつ逆向きに回す | 手前の六角の組子ほど大きく動く | 一目で和柄と分かる。成長の意味がある | 線の量が多く、最もにぎやか |
| C 折り紙 | ミウラ折りの剛体折り。スクロールで折り具合が変わる | カーソルで傾き、スクロールで折り畳み | 立体で印象に残る | 和の静けさより技術の見せ場の印象が強い |

描画は共通の WebGPU レンダラーで行う。線・円・点はインスタンス描画した四角形の中で距離関数からアンチエイリアスし、ミウラ折りの面は深度バッファ付きの三角形で描く。同じ図形データを Canvas 2D でも描けるため、WebGPU 非対応時は Canvas 2D に切り替える。

## 実績の候補
| 案 | 見せ方 | 向いている点 | 気になる点 |
| --- | --- | --- | --- |
| A 絵巻 | 12件を新しい順に横一列へ並べ、縦スクロールで横に進む（スマートフォンは横スワイプ）。下の線が年表 | 時系列の流れが伝わる。全件を大きな画像で見せられる | 一覧性が低い。件数が増えると長くなる |
| B 展示室 | `isPinned` の5件を1画面1件で展示し、背面に年号を大きく置く。残りは最後に一覧 | 代表作の印象が強い。パララックスが自然に効く | 代表作以外は小さく扱われる |
| C 目録 | 年ごとの見出しと表形式の一覧。ホバーで画像がカーソルについてくる | 一覧性が最も高い。件数が増えても崩れない | 画像の印象は弱め |

おすすめは **Hero A（算額）× 実績 B（展示室）**。モックアップを開いた直後はこの組み合わせを表示する。

## パララックス
| 場所 | 動き | きっかけ |
| --- | --- | --- |
| Hero | 図形を奥・中・手前の3層に分け、層ごとに動く量を変える。見出しは速く上へ流れて薄くなる | スクロール、カーソル |
| About | 七宝の円窓が文字よりゆっくり動く | スクロール |
| Works | 絵巻は横移動と画像のずれ、展示室は年号と画像の速度差、目録はプレビューの追従 | スクロール、カーソル |
| Profile | 背後の金の円と写真の動く量を変える | スクロール |
| Contact | 青海波が背景としてゆっくり動く | スクロール |

`prefers-reduced-motion` ではすべて止める。変形は `transform` だけを使う。

## 実装ステップ（案が決まった後）
1. 配色トークンを深緑と金に絞り、ライトテーマ用の値と `ThemeToggle` を外す
2. `src/lib/canvas/` に共通の描画ループとベクターレンダラー（WebGPU / Canvas 2D）をまとめる
3. 選んだ Hero を `client:idle` の island として組み込む
4. 選んだ実績の見せ方で `Achievements` と `AdditionalAchievements` を置き換える
5. パララックスを共通のユーティリティにし、各セクションへ適用する。Lighthouse CI で LCP と TBT を確認する
