# スキルデータ共通化 実装計画書

## 概要
スキル情報を「スキル単位の単一ソース + 役割/カテゴリの辞書 + 画面用セレクタ」で再設計し、/about/skills の表示を全て共通データから生成する。

## 背景
- スキル情報が複数コンポーネントに分散し、表記揺れや更新漏れが発生しやすい。
- スキル単位の情報整理と、表示用途別の派生ビューの両立が必要。

## 目的
- スキル情報の正確性と一貫性を高める。
- UI表示はセレクタ結果のみに依存させ、実装を単純化する。
- 将来的な翻訳や拡張に耐える構造にする。

## 方針
- **単一ソース**: `skills` を事実データの中心にする。
- **正規化**: `categories` / `roles` / `tags` は辞書で定義。
- **派生ビュー**: UIは `selectors` の結果のみを使用。
- **i18n**: 表示文言は辞書側に寄せる。

## 変更範囲（予定）
- データ定義
  - `src/data/skills.ts`（再構造化）
  - `src/data/skills-taxonomy.ts`（カテゴリ/ロール/タグ辞書）
- セレクタ
  - `src/lib/skills/selectors.ts`
- UI
  - `src/components/about/skills/skill-summary.tsx`
  - `src/components/about/skills/skill-capabilities.tsx`
  - `src/components/about/skills/skill-stack.tsx`
  - `src/components/about/skills/skill-development.tsx`

## データ設計（案）
### skills（単一ソース）
- `id` / `name`
- `categoryIds: string[]`
- `roleIds: string[]`
- `tags: string[]`
- `startDate`
- `proficiency`
- `summary`
- `strengths[]`
- `useCases[]`
- `projects[]`
- `links[]`
- `learning[]`
- `interests[]`

### taxonomy（辞書）
- `categories`: id/label/description
- `roles`: id/label/description
- `tags`: id/label

### selectors（派生ビュー）
- `getSkillSummary()`
- `getSkillCapabilities()`
- `groupSkillsByProficiency()`
- `getSkillDevelopmentItems()`

## ヒアリング項目（スキル単位）
各スキルについて、以下を確認して正確なデータに更新する。

1. 開始時期
- いつから実務/学習を開始したか（YYYY-MM-DD）

2. 習熟度
- `expert / advanced / intermediate / beginner` のどれが適切か

3. 主な用途・成果
- 実務での具体的な利用場面（useCases）
- 代表的なプロジェクト（projects）

4. 強み
- 得意分野・強み（strengths）

5. 学習・関心
- 現在学習中のトピック（learning）
- 今後の関心（interests）

6. 役割・カテゴリ
- フロント/バック/インフラ/モバイル等の役割
- カテゴリ（frontend/backend/db/infra/tool/ai など）

## 進行ステップ
1. **設計確定**
   - taxonomy と skills 型定義を確定
2. **ヒアリング実施**
   - 既存スキルごとに上記項目を確認
3. **データ再構築**
   - `skills.ts` を新構造に移行
4. **セレクタ実装**
   - UI用途に合わせた派生データ生成
5. **UI置き換え**
   - skillsページの全コンポーネントをセレクタ参照に統一
6. **検証**
   - 表示差分・欠落の確認

## 受け入れ基準
- /about/skills の全表示が共通データから生成される
- スキル情報の更新は `skills.ts` のみで完結する
- 表記揺れがなく、役割/カテゴリ/タグが辞書に統一される
