# 個人開発を実績（works）と並列表示する 実装計画書

> 関連: #50（作業計画の合意）/ #49（キャリア・現職情報の再構築）
> 本書は #50 で合意した方針を記録し、実装を別issue/PRへ分割するための計画書。

## 概要
個人開発プロダクト群（`zedi` / `typeflow` / `career-gems` / `skill-quest-ai` 等）を実務実績と「並列」に見せるため、works の一覧・データ・ナビを再設計する。種別を `category`（働き方軸）と `kind`（実務/個人開発軸）の2軸に整理し、一覧を `/works` へ統合する。

## 背景・目的
- 現状、個人開発は `category: 'personal'` として実務実績（company/freelance）からフィルタで分離され、別ページ（`/works/personal`）にもサイロ化している。
- ブランディング上、個人開発（AI活用プロダクト群）は強みの証憑であり、実務実績と「並列」に見せたい。

## 現状（実装）
- **データ**: `src/data/works.ts` / 型 `src/types/works.ts`（`Work.category = 'company' | 'freelance' | 'personal'`）。
  - 件数: 全13件中 `personal` 11件 / `freelance` 2件 / `company` **0件**。`isPinned` は personal の5件のみ。
- **一覧**: `/works`（`WorksFilter` 全件＋フィルタ）、`/works/personal`・`/works/company`・`/works/freelance`（`initialCategory` 違いだけのほぼ同一ページ）。
- **ホーム**: `Achievements`（`isPinned` のfeatured枠）＋ `AdditionalAchievements`（category チップ＋検索、`getAllWorks().slice(0,6)`）。
- **ナビ**: `src/data/navigation.ts` の Works 配下に Company / Freelance / Personal サブ項目。Footer も同様。
- **i18n**: `src/data/homepage.ja.ts` / `homepage.en.ts` の `additionalAchievements.categories`、`public/locales/*/common.json`。

## 合意した方針（#50）
| 論点 | 決定 |
| --- | --- |
| 並列表示の定義 | **案A**: 一覧を1つに統合し、種別（実務/個人開発）は **バッジ表示＋任意フィルタ** で silo を解消 |
| データ/型 | **`kind: 'professional' \| 'personal'` 軸を新設**。`professional` 配下に `company`/`freelance` を内包 |
| サブページ | **`/works` に統合し、旧URLは301リダイレクト** |
| company実績 | **今後追加する**（実務実績を載せる前提で型・UIを設計し、個人開発と見せ分け） |

## データ設計（案）
### Work 型の拡張（`src/types/works.ts`）
```ts
export type WorkKind = 'professional' | 'personal';
export type WorkCategory = 'company' | 'freelance' | 'personal';

export interface Work {
  // 既存
  slug, title, description, status, thumbnail, technologies,
  github_url, website_url, created_at, updated_at, isPinned?;
  // 軸の2分化
  kind: WorkKind;          // 実務 / 個人開発（並列表示の主軸）
  category: WorkCategory;  // 働き方の細目（company/freelance/personal）
}
```
- 移行: 既存データに `kind` を付与。
  - `category: 'company' | 'freelance'` → `kind: 'professional'`
  - `category: 'personal'` → `kind: 'personal'`
- `company` は今後追加する前提で型・セレクタに残置（現状0件でもUIは耐える設計）。
- 並べ替え基準: **`isPinned` → `updated_at` 降順** を既定とする。

### セレクタ（`src/data/works.ts`）
- 既存 `getWorksByCategory` は維持しつつ、`getWorksByKind(kind)` を追加。
- `getAllWorks()` の並び順を `isPinned → updated_at` で安定化（ホーム先頭6件の質を担保）。

## UI実装範囲
1. **`WorkCard`（`src/components/works/WorkCard.tsx`）**
   - 種別バッジを追加（例: 「実務」/「個人開発」）。アクセシブルなラベル付き。
2. **`WorksFilter`（`src/components/works/WorksFilter.tsx`）**
   - 主フィルタを `kind`（すべて/実務/個人開発）に変更。`category` は副次フィルタまたは廃止を検討。
   - `initialCategory` → `initialKind` 系へ整理（リダイレクト互換のため query 受け取りも検討）。
3. **`AdditionalAchievements`（`src/components/home/AdditionalAchievements.tsx`）**
   - category チップを `kind` ベースに変更し、実務/個人開発を並列に切替可能化。
   - 並び順をセレクタ側の既定（isPinned→updated_at）に合わせる。
4. **`Achievements`（注目枠）**
   - featured に個人開発が偏らないよう、実務/個人開発が混在し得る前提を明記（company追加後を見据える）。

## ルーティング / ナビ
- `/works` を統合一覧に一本化。
- `/works/personal`・`/works/company`・`/works/freelance` は **301リダイレクト**（`/works?kind=...` 等へ）。
  - Astro での実装方法（`Astro.redirect` または `astro.config` の `redirects`）は実装PRで確定。
- `src/data/navigation.ts` / Footer の Works サブ項目を整理（実務/個人開発の2項目 or 統合一覧のみ）。
